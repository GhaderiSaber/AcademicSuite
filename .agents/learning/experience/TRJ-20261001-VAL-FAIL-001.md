### 3.2 OpenXML Specification & Forensic Invariant
In ISO/IEC 29500-1 (Office Open XML File Formats), the schema for Table Properties (`CT_TblPr`) defines a strict sequence of permissible child elements. Specifically, `<w:bidiVisual/>` (which instructs Word to render columns Right-to-Left) must appear before `<w:tblW>` (table width) or at the top of the property list:
```xml
<xsd:complexType name="CT_TblPrBase">
  <xsd:sequence>
    <xsd:element name="tblStyle" type="CT_String" minOccurs="0"/>
    <xsd:element name="tblpPr" type="CT_TblPPr" minOccurs="0"/>
    <xsd:element name="tblOverlap" type="CT_TblOverlap" minOccurs="0"/>
    <xsd:element name="bidiVisual" type="CT_OnOff" minOccurs="0"/>
    <xsd:element name="tblStyleRowBandSize" type="CT_DecimalNumber" minOccurs="0"/>
    <xsd:element name="tblStyleColBandSize" type="CT_DecimalNumber" minOccurs="0"/>
    <xsd:element name="tblW" type="CT_TblWidth" minOccurs="0"/>
    ...
```
[`academic_chapter_auditor.py`](.agents/validators/academic_chapter_auditor.py#L289-L295) enforces this strictly:
```python
bidi_idx = list(tblPr).index(bidi)
tblW = tblPr.find('w:tblW', NS)
if tblW is not None:
    tblW_idx = list(tblPr).index(tblW)
    if bidi_idx > tblW_idx:
        bidi_errors.append(f"Table {idx} <w:bidiVisual/> must precede <w:tblW>.")
```

### 3.3 Root-Cause Code Execution Trace
In [`02_analysis_code/compile_gold_standard_chapter4.py`](02_analysis_code/compile_gold_standard_chapter4.py):
1. **Preamble Tables (Tables 1 to 11)**:
   Copied verbatim from [`03_deliverables/Chapter_4_Preamble_Source.docx`](03_deliverables/Chapter_4_Preamble_Source.docx) (or the backup `Chapter_4_Results~20260929-235350.docx`). In these tables, `<w:bidiVisual/>` was already properly positioned or preceded `<w:tblW>`.
2. **Newly Generated Tables (Tables 12 to 25)**:
   Every new table appended in Sections 4-4 to 8-4 was created via `table = doc.add_table(...)`. In `python-docx`, `add_table` creates a default `<w:tblPr>` containing `<w:tblW w:w="0" w:type="auto"/>` at index 0.
3. **Flawed Insertion in Helper**:
   The table styling helper `apply_table_apa7_and_bidi` originally contained:
   ```python
   def apply_table_apa7_and_bidi(table, col_widths=None):

   ```
   Calling `.append(bidi)` appended the element after `<w:tblW>`, establishing `bidi_idx > tblW_idx`.
4. **Why `patch2.py` Failed to Remedy the Defect**:
   On `2026-09-30T20:25:30Z`, [`patch2.py`](02_analysis_code/patch2.py) was executed. However, `patch2.py` only patched line 422 inside `post_process_openxml`:
   ```python

       tblPr = tbl._element.xpath('w:tblPr')

           if not tblPr[0].xpath('w:bidiVisual'):
               tblPr[0].insert(0, parse_xml(f'<w:bidiVisual {nsdecls("w")} w:val="1"/>'))
   ```
   Because `apply_table_apa7_and_bidi` had *already* appended `<w:bidiVisual/>` to tables 12-25, `tblPr[0].xpath('w:bidiVisual')` returned a non-empty list. Thus, `post_process_openxml` skipped tables 12-25 completely, leaving the invalid element order (`<w:tblW>` followed by `<w:bidiVisual/>`) intact on disk.
