## 4. Root-Cause Analysis: Why Was the Writer Instructed to Mutate the JSON?

Forensic inspection of the agent interaction logs and skill definitions isolates four distinct root causes:

### 4.1 Orchestrator Role Boundary Conflation in Task Delegation
`academic-orchestrator` conflated **deliverable packaging** with **content responsibility**:
- Under Directive 3 (Triad Invariant), the orchestrator was tasked with delivering `.docx`, `.md`, and `.json` for each micro-stage.
- When delegating Stage 4D.2 to `academic-writer`, the orchestrator simply listed all three file types in the `required_artifacts` list and added the acceptance criterion: *"Synchronize 03_deliverables/02_descriptives_and_reliability.json"*.
- The orchestrator failed to enforce that `.json` result payloads belong exclusively to `statistics-agent`. The correct instruction should have been for the orchestrator to copy or link `02_descriptives_payload.json` to `02_descriptives_and_reliability.json`, or to instruct `academic-writer` strictly to author `.docx` and `.md` while referencing `02_descriptives_payload.json` as read-only input.

### 4.2 Triad Scaffolding Script Design Flaw (`scaffold_chapter4_triad.py`)
In `.agents/skills/chapter-4-writing/scripts/scaffold_chapter4_triad.py`, the skill provides a utility that scaffolds `{base_name}.docx`, `{base_name}.md`, and `{base_name}.json`:
```python
stage_data = {
    "stage": stage_name,
    "base_name": base_name,
    "triad_complete": True,
    "status": "STAGE_INITIALIZED"
}
with open(json_path, 'w', encoding='utf-8') as f:
    json.dump(stage_data, f, indent=2)
```
This script teaches the writing agent that `{base_name}.json` is a light document-metadata stub to be scaffolded alongside narrative text, rather than a rich mathematical payload generated by statistical analysis packages.

### 4.3 Stage 4B vs Stage 4D File Naming Asymmetry
In all other analytical micro-stages:
- Stage 4.4: `statistics-agent` wrote `04_correlations_payload.json` AND `04_correlations.json` (both 158,948 bytes, 100% identical).
- Stage 4.5: `statistics-agent` wrote `05_macro_model_payload.json` AND `05_macro_model.json` (both 26,157 bytes, 100% identical).
- Stage 4.6: `statistics-agent` wrote `06_hypothesis_1_payload.json` AND `06_hypothesis_1.json` (both 31,827 bytes, 100% identical).
- Stage 4.7: `statistics-agent` wrote `07_hypothesis_2_payload.json` AND `07_hypothesis_2.json` (both 23,561 bytes, 100% identical).
- Stage 4.8: `statistics-agent` wrote `08_mediation_analysis_payload.json` AND `08_mediation_analysis.json` (both 57,607 bytes, 100% identical).

In Stage 4.2, however, `statistics-agent` wrote `02_descriptives_payload.json`, but **did NOT** write `02_descriptives_and_reliability.json`. This left a naming void in `03_deliverables/`. When Stage 4D.2 was executed, `academic-writer` stepped into this void and created a new file with the canonical name, structuring it as a table stub.

### 4.4 Absence of PreToolUse File-Writing Hook on `academic-writer`
While `academic-writer.md` contains strict declarative rules:
- *"The Phase 12 Writing Invariant: The Writer Never Becomes a Second Statistician"*
- *"The academic writer must never recalculate, round, approximate, or alter statistical parameters in their head"*
There was no mechanical `PreToolUse` hook intercepting `write_to_file` when called by `academic-writer` on `.json` paths within `03_deliverables/`. The writer was able to overwrite the deliverable JSON without encountering a guard exception.
